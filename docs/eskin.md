# 设想：把 VCM 用到离电型电子皮肤的触觉信号上

_2026-10-28 · 讨论记录，尚未开工。项目负责人的主方向是离电型（iontronic）电子皮肤，这里记下 VCM 能借给它什么、借不了什么。_

## 一句话

VCM 不是一种“数据格式”，它管的是**一堆可复用模块怎样组合、怎样被更新而不伤到旧用途**。
把触觉信号“转写成器件无关的通用表示”这一步，VCM 本身做不了，要靠“器件专属编码器 + 共享潜空间”（T3、TactX、AnyTouch 已在光学触觉上这样做）；
VCM 能接手的是这一步**之后**的长期维护：器件老化与漂移、重新标定、新器件加入、新任务一个个累积时，旧的解码器还能不能用。

## 对应关系

| VCM 组件 | 在离电型电子皮肤上对应什么 | 是否对口 |
|---|---|---|
| 基础单元 | 每个器件（或批次）的前端编码器：原始电容 / 阻抗 → 共享潜空间；共享主干的各层；各任务的解码头 | 对口 |
| 版本号 + 惰性函数空间检查 | 器件老化、水凝胶失水、重标定后前端编码器版本 +1；下游任务头被调用时，用留存的参考按压检查准确率，不合格就退回旧快照或触发重标定 | **最对口**，且给 VCM 主线提供了一个真实的“共享模块被原地改写”场景 |
| 条件变量 $A\mid T_1,\ B\mid T_2$ | 同一压力在不同温度 / 湿度下电容不同——不是矛盾，是漏了隐藏变量。离电型器件的离子弛豫时间本身随温度变，You et al.（Science 2020）只用两个测量频率就把温度与应变解开，所以条件变量可以由器件自己测出 | 对口，物理与结构恰好吻合 |
| 多维相似度指针 | 器件之间的相似度分维度记：材料与结构、标定曲线形状、响应动力学（弛豫时间、迟滞）、任务语义；新器件来时据此挑从哪个旧器件迁移 | 对口 |
| 角色绑定 | 角色 = 位置 / 模态（法向力、剪切、振动、温度）/ 时间尺度。作为“槽”的结构有用 | 只借结构；不建议把 HRR 原样套在原始信号上（噪声累积，学到的编码器更好） |
| 晋升 | 常用且稳定的组合（如“滑移检测”）晋升为原语，供“抓握是否稳定”“材质识别”等上层任务复用 | 有条件：v0.2 的结果是只在少样本时有用（100–250 个样本 +1~3 个百分点），恰好对应触觉标注贵的现实 |

一个值得一试的“转写”分层：第一层转写成**标定后的物理量**（压力 kPa、剪切、温度 °C），它天然与器件无关；
学到的潜表示只负责物理量表达不了的部分（纹理振动、接触的时空模式）。这样“通用”的那部分有物理意义，审稿时也好讲。

## 要先说清的风险

1. **VCM 主线还没过证伪实验**（函数空间惰性检查 vs DEN 式权重空间检查，见 `STATUS.md` 下一步 1）。证据目前只在 MNIST 与小 CNN 上。
   电子皮肤这条线应定位为“漂移 / 多器件场景下的持续学习”，VCM 是候选方法之一，与重标定、ER、EWC、DEN 式检查同台比较，不预设它赢。
2. **惰性检查要存带标签的留存样本**（现在每个旧任务 200 个）。在实验室可以用标准压头 / 砝码做一组参考按压当标定集；部署场景里拿不到标签时需要另想办法。
3. **数据**：离电型阵列没有光学触觉那样的大规模公开数据集（T3 用的 FoTa 是 13 种传感器，几乎都是光学的），要自己采，采集协议（频率、采样率、压头、温湿度记录）要先统一。
4. **漂移的物理根源**（失水、离子液体电导随温度变化、粘弹性蠕变、电极界面）里，能在材料端解决的部分，算法补偿说服力有限；论文要分清两者。
5. 简单检索里没找到“离电型电子皮肤 + 持续学习应对漂移”的工作；最接近的是软体手指压电应变传感器的持续学习漂移补偿（arXiv 2503.16540）。没搜到不等于没有，开题前要系统查一遍。

## 最小可行路线

1. **先证伪（只用已有数据）**：把不同批次器件当作不同域、按时间切片（第 1 / 7 / 30 天）当作漂移，测“每次重标定或微调之后，旧任务头掉多少”。
   掉得不明显，VCM 的版本机制在这里就没有用武之地，早知道早省事。
2. **方法比较**：器件编码器 + 共享主干 + 任务头；比较 freeze、原地微调、原地微调 + 惰性检查退回、DEN 式权重漂移阈值、ER。
   指标：新器件达到目标精度所需的标注样本数、旧任务遗忘、额外存储与维护计算。
3. **条件变量**：用双频测得的温度作条件，比较“按温度条件存储”与“直接微调”在温度循环下的表现。

## 对接方案（材料端 ↔ 仓库）

分工：材料端负责器件、有意制造的“变化”和按协议采集的数据；仓库负责读数据、搭模型、跑对比。
第一批数据到了再写 `vcm/cl/data.py` 里的 `eskin` 基准（按真实的数组形状写，不提前猜）。

### 两个场景对应 VCM 的两条不同分支

| 场景 | 发生了什么 | VCM 该做什么 | 旧任务用什么数据检查 |
|---|---|---|---|
| A. 多器件 | 器件 B 加入，共享主干被原地微调 | 器件 A 的任务被查询时惰性检查，不合格就**退回旧快照** | A 最近一次采集的留存样本（A 本身没变，退回有意义） |
| B. 漂移 | 同一器件老化，前端被重新标定，版本 +1 | 下游任务头被查询时惰性检查，不合格就**用新数据重新拟合**（版本不一致 → 重组） | **当下**重新采的参考按压 |

**评测陷阱：** 场景 B 里不能用第 0 天的测试集测旧任务。器件已经回不到第 0 天，退回旧快照会在旧测试集上显得完美，
实际上只是记住了过去的器件。漂移场景的所有测试都用当前器件状态下采的数据。

### 采集协议

- **参考按压集**：固定点位 × 固定几档力 × 重复几次（约 100 次），**每次采集开头都先跑一遍**。
  它同时用于重新标定、VCM 的裁判样本和漂移的度量，是整个对接的核心。
- **任务数据**：由电动位移台 + 力传感器 + 3D 打印压头自动产生，标签由台子给出，不需要人工标注。
  起步任务：按压位置（分类）、力的档位（分类，同时保存连续力值）、压头形状（分类）；有滑动台再加纹理 / 滑移。
- **变化**：3–4 个器件，有意改变配方或工艺（材料端本来就要做的配方对比）；每个器件在第 0、7、14、30 天各采一次，另做一次温度循环。
- **同步**：一个脚本同时控制位移台、读力传感器和读电容 / 阻抗，统一用主机时间戳。
- 起步规模建议：4×4 阵列就够；做条件变量需要能在两个频率上测阻抗（LCR 表或阻抗测量芯片），只能测单频时先用温湿度计读数当条件。

### 数据格式（每次采集一个 `.npz` + 一个 `.json`）

```
<device>_<YYYYMMDD>_<session>.npz
  x        float32 [N, F, H, W, T]   F = 测量频率数，H×W = 阵列，T = 每次按压的时间采样点
  is_ref   bool    [N]               是否属于参考按压集
  pos      int     [N]               按压点位编号（-1 = 无）
  force    float32 [N, T]            力传感器同步曲线（N）
  shape    int     [N]               压头形状编号
  baseline float32 [F, H, W, T0]     空载基线
<同名>.json
  device_id, batch, recipe（配方参数）, fab_date, session_date,
  temp_C, RH, freqs_Hz, sample_rate_Hz, array_layout, stage（压头列表、点位坐标、速度）, notes
```

### 对材料端的回报

“标定后下游解码器还能保留多少准确率、需要多少次参考按压才能恢复”可以作为材料的一个评价指标，
补在灵敏度、迟滞、蠕变、循环稳定性之外：它直接回答这块材料做成的皮肤能不能长期被同一套算法使用。
这是一个设想中的指标，不是领域里的通行标准，用的时候要说明定义。
