# 设计说明：README 的每个组件落在代码的哪里

本文件回答两个问题：README 里的每个想法在代码里是怎样实现的；在神经网络上，它被具体化成了什么。
凡是 README 没有规定、由实现者自行决定的地方，都标注为 **〔实现选择〕**，方便以后推翻重来。

## 1. 符号层：六个组件的直接实现

| README 组件 | 代码 | 要点 |
|---|---|---|
| 基础单元，独立存储 | `vcm/units.py` → `UnitStore` | 每个单元属于一个领域分区（`domain`）；`update` 只改一个单元。 |
| 版本号 | `Unit.version`，`UnitStore.update` | 每次修改 +1，并通知订阅者（立即失效策略要用）。 |
| 快照引用（写时复制） | `Snapshot`，`UnitStore.pin / unpin` | 快照是只读副本；被引用计数钉住的旧版本会保留，无人引用时释放。 |
| 多维相似度指针 | `vcm/similarity.py` → `SimilarityProfile`、`Pointer`、`SimilarityIndex` | 指针 = 目标单元 + 被钉住的版本 + 角色 + 多维相似度。检索时按某一维排序/过滤。 |
| 角色绑定组合 | `vcm/compose.py` → `Composer` | $v=\sum_r r\circledast f_r$，循环卷积；角色向量取幺正向量，解绑对目标项精确，残余串扰由清理记忆（`ItemMemory`）消除。 |
| 条件变量 | `vcm/conditional.py` → `ConditionalKnowledge` | 固定属性冲突 → 记录矛盾、等外部裁决；可变属性冲突 → 从上下文里找能区分两条知识的变量，找不到就引入占位隐藏变量。 |
| 组合缓存 + 惰性失效 | `vcm/cache.py` → `CompositionCache` | 每条缓存记录依赖版本；读取时比对；不一致时按策略重组/删除，或交给外部裁决（`judge`）决定“重组 / 删除 / 保留旧值”。 |
| 外部反馈 | `CompositionCache.feedback`、`judge` | `feedback(key, ok=False)` 删除错误缓存并阻止其晋升；`judge` 在过期时被调用。 |
| 晋升 | `vcm/promotion.py` | 命中次数 ≥ 阈值、连续稳定命中 ≥ 阈值、无负面反馈 → 生成概念单元；层级 = 依赖的最高层级 + 1。 |
| 保持 / 切断依赖 | `PromotionMode.KEEP_DEPS / CUT_DEPS` | keep：概念记住配方，部件变了就惰性重建；cut：独立存在，可用 `VCM.drift` 量化与原料的偏离。 |
| DAG 约束 | `UnitStore.add / set_deps` 的层级检查，`vcm/graph.py` | 依赖只能指向更低层级，因此版本检查的递归（`VCM.fresh_version`）一定终止。 |

〔实现选择〕README 说“所有指针只指向更底层的单元”。我们把**依赖指针**（组合 → 部件）和**横向相似度记录**
（两个同层单元有多像，比如西语 salir 与法语 salir）分开：前者受 DAG 约束、参与版本检查；
后者存在 `SimilarityIndex` 里，只用于检索候选，不产生依赖。

〔实现选择〕组合本身（缓存条目）不是单元；只有晋升之后它才成为可以被指向的单元。这正是“晋升后的概念可以被其他组合指向”的含义。

## 2. 神经层：同一套机制放到网络上

### 2.1 对应关系

| VCM 概念 | 神经网络里的对应物 |
|---|---|
| 基础单元 | 网络的一个“角色槽”（MLP：`in / hidden / out`；CNN：`block1..3 / fc / head`）的一份参数，存成 state-dict 快照 |
| 领域 | 创建该单元的任务 |
| 指针 | 新任务复用某个旧单元，钉住其版本；附带相似度：`form`（输入统计相似度）、`semantic`（标签名重合度）、`category`（粗类别重合度，如 CIFAR-100 超类）、`function`（复用后在验证集上的准确率） |
| 角色绑定 | 任务的网络 = 每个槽绑定**一个**单元，按顺序执行；从不对多个单元做加权平均 |
| 条件变量 | 任务身份本身。测试时若没给任务编号，用输入的最近质心推断（`TaskRouter`） |
| 组合缓存 | 每个任务组合出的网络（`Frozen` 层直接引用快照张量，不复制），记录所依赖的单元版本 |
| 修改基础单元 | `update` 模式下，新任务会以较小学习率在原地继续训练被复用的单元 → 版本 +1 |
| 惰性失效 + 外部反馈 | 旧任务下一次被使用时比对版本；过期则由“裁判”（该任务反馈缓冲区上的准确率）决定：接受新版本 / 修复本任务私有单元 / 保留旧快照 |
| 晋升 | 若干连续的共享单元被多个任务反复使用且期间版本不变 → 晋升为跨多个角色的概念单元 |

### 2.2 学一个新任务的流程（`VCMLearner.learn`）

1. **画像**：计算输入均值/标准差向量、标签名集合、粗类别集合。
2. **生成候选组合**（〔实现选择〕）：
   - 从零开始（全部新单元）——始终保留；
   - “底部复用”：前 *k* 个角色沿用 `form` 最相似的旧任务的单元（要求 `form ≥ 0.3`）；
   - “顶部复用”：从第 *k* 个角色起沿用 `semantic` 最相似的旧任务的单元（要求 `semantic ≥ 0.5`）；
   - 已晋升的概念：作为一个整体填入它覆盖的角色槽，优先评估。
   这就是“多维相似度避免假朋友”在网络上的样子：Permuted MNIST 的任务之间 `form ≈ 0.03`、`semantic = 1`，
   于是只复用上层；Split CIFAR 的任务之间 `semantic = 0`，于是只复用下层。
3. **探测**：每个候选训练 `probe_steps` 步，在验证集上比较；在最优准确率 0.5% 以内的候选里选新参数最少的（简约原则）。
4. **完整训练**被选中的组合（总步数与其他方法相同；探测的步数计入额外开销）。
5. **提交**：新单元入库（版本 1）；`update` 模式下被训练过的复用单元写回，版本 +1；
   把任务的组合放入缓存并钉住所用快照；记下它在反馈缓冲区上的参考准确率 `ref_acc`。
6. **维护**：`eager` 立刻检查所有过期任务；`lazy` 什么也不做，等它们被用到。

### 2.3 过期任务的裁决（`VCMLearner._judge`）

```
fresh = 用当前版本重新组合
if acc(fresh, 反馈缓冲区) ≥ ref_acc − tolerance:   接受（重组，旧快照若无人引用即释放）
elif 能修复：在 2/3 缓冲区上重训本任务私有单元，在其余 1/3 上验收 → 通过则接受（私有单元版本 +1）
else: 保留旧快照（KEEP）——答案与学完时完全一致，代价是旧快照继续占内存
```

`ref_acc` 固定为任务刚学完时的值，所以多次更新累积的下降也不会超过 `tolerance`（以缓冲区估计为准）。

**实验教训**（`results/pmnist_stress*`）：缓冲区估计是偏乐观的——v0.1 默认的反馈样本取自训练集，模型在它们上面过拟合，
测得的下降小于测试集上的真实下降；“修复”只在 1/3 缓冲区（约 67 个样本）上验收，更容易蒙混过关。
因此 `--feedback-source val`（用留出的验证样本当裁判）是更稳妥的设置，而 `repair_steps=0`（不合格就保留旧快照）
在两种设置下都是最好的配置。v0.1 之后这两项已成为默认值（`VCMConfig` 与 `run_cl.py`）；v0.1 的结果用旧默认
（`--feedback-source train --repair-steps 100`）跑出，`run_suite.sh` 里显式写明。`--eval-split val` 时裁判自动改用训练样本，
以免裁判与测量用同一批数据。

**v0.6：换裁判（`VCMConfig.judge`）。** 上面的是 `judge="function"`（默认，代码路径与之前逐位一致）。另有两个不用数据的权重空间裁判，
用于与 DEN（ICLR 2018）式的判断比较：`weight_rel` 看过期单元相对它被钉住的版本的整体变化 $\lVert \theta' - \theta \rVert_2 / \lVert \theta \rVert_2$，
`weight_neuron` 看单个神经元（`Linear` 的一行、`Conv2d` 的一个输出通道）输入权重的最大 L2 变化（DEN 的 $\rho_i$）；
多个单元过期时取最大值，不超过 `drift_threshold` 就接受。权重空间裁判不修复（修复要用数据）。
〔实现选择〕权重变化相对于该任务正在用的（被钉住的）版本计算，所以留下旧版本后再来的更新，量的是累积变化。

诊断：`judge_log=True` 时每次裁判记下三种统计量，以及新版本在该任务验证集里、反馈缓冲区之外的样本上的真实降幅（裁判看不到这些样本，不计入计算量）。
`run(..., settle=True)`（`--settle`）在最后一次测量之后把所有还没轮到检查的过期组合都检查一遍，再记录保留的旧快照，
这样“还没轮到检查”不会被算成“决定保留”；最终 ACC 不受影响（测量时的预演 `_view` 本来就按同一个裁判给出答案）。

### 2.4 测量协议（`vcm/cl/runner.py`）

每学完一个任务：

1. **服务**：20 批 × 100 个查询，任务按 $p(j)\propto 1/(\text{age}_j+1)$ 抽取（越新的任务越常被问）。
   惰性维护只在这里被触发。
2. **测量**：在所有已学任务的测试集上算准确率。VCM 用 `evaluate`，即“如果此刻被问到会怎么答”——
   过期的任务会做一次不落盘的裁决预演，不改变任何状态、不计入计算量。

### 2.5 基线

- **Fine-tune**：一个共享网络依次训练（下限）。
- **EWC**：Online EWC，经验 Fisher（1000 个样本的逐样本梯度平方），λ 在验证集上选。
- **ER**：每任务存 `--buffer` 个样本，每个批次 1:1 混入回放；与 VCM 反馈缓冲区等量。
- **Independent**：每个任务一个全新网络（零遗忘、零迁移、内存线性增长）。
- **GRACE-CL**：GRACE 的码本机制改编到分类持续学习，改编点见 `vcm/cl/learners/grace.py` 文件头。
- **MNTDP-D**（v0.4）：按官方实现（github.com/TomVeniat/MNTDP，配置 `PSSN-search-6-fw`）复现在我们的角色槽上：
  15 近邻先验选出最相似的旧任务，候选 = 复用它的前 k 层（k = 0 … 除输出层外全部）+ 其余新建，每条路径训满、按验证准确率挑，旧模块冻结。
  改编点（写在 `vcm/cl/learners/mntdp.py` 文件头）：每条路径训练的步数与其他方法训练一个网络相同（官方代码训到收敛并做小的学习率网格）；
  有模板时只复用角色对齐的前缀；先验本身的计算量（前缀的前向 + 近邻距离）计入总计算。它复用 VCM 的冻结单元存储与服务代码，
  因为单元从不更新，所以不涉及版本检查、裁判或晋升。

### 2.6 模板 + 角色槽，与整条组合的晋升（v0.2）

v0.1 的网络是“固定的一列角色”：每个任务的网络都是同一张角色表（MLP：`in / hidden / out`），复用只能按位置进行。
为了检验“晋升出的概念能不能当积木”，v0.2 把它推广成**模板**（`vcm/cl/models.py` → `Template`）：

| 模板 | 角色槽 | 读图部分（逐个输入项） | 用于 |
|---|---|---|---|
| `unary` | `in, hidden, out` | `in, hidden` | 单图任务（digit、parity）；与 v0.1 的 MLP 完全一样 |
| `binary` | `in, hidden, mix, out` | `in, hidden`（两张图共用同一个读图器） | 两图任务（sum、equal、greater、diff） |

- 读图部分的层只作用在最后一维，所以同一个读图器可以同时处理一对图（输入形状 `N × 2 × 784`）；`mix` 先把两份编码拼起来。
- 角色工厂按输入宽度建层（`Architecture.build`）：读图器换成输出 10 维的概念时，后面的 `mix` 自动变成 `Linear(2·10, 256)`。
- 固定架构（Permuted MNIST 的 MLP、CIFAR 的 CNN）只有一个 `default` 模板，代码路径与 v0.1 一致：
  在相同命令下，v0.1 的 10 种方法重跑得到**逐位相同**的准确率矩阵、计算量与裁决次数（改动时用旧代码对拍过）。

**复用规则**（`VCMLearner._candidates`）：

1. **逐层复用**（v0.1 的“底部 / 顶部复用”）：旧单元保持它在原模板里的位置，只能放到新模板里**同名角色**的位置上；
   〔实现选择〕顶部复用（输出头）只在同一种模板的任务之间进行。所以两图任务可以复用 digit 的 `in, hidden`，
   却永远拿不到 digit 的输出层——它在 `unary` 里是最后一层，在 `binary` 里那个位置是 `mix`。
2. **共享块晋升**（v0.1）：被多个任务共用、期间版本不变的一串连续单元 → 概念，仍按原位置使用。
3. **整条组合晋升**（v0.2，`promote_compositions`）：README 原文是“一条**缓存**如果被频繁调用且长期稳定……就晋升为概念节点”。
   在神经层上缓存条目就是一个任务组合出的整张网络。条目被命中 ≥ `promote_min_hits` 次、连续有效命中 ≥ `promote_min_stable` 次、
   没有负面反馈（复用符号层的 `PromotionPolicy.eligible`）→ 晋升为概念，输入是一个图、输出是该任务的类别（digit 的概念输出 10 维）。
   这样的概念可以**整体填入任何模板的读图槽**（`Slot(0, reader, concept)`），例如 `binary` 的两个图槽同时由“读数字”填。
   〔实现选择〕只晋升单输入的组合（只有读图槽能接它们）；概念候选要求新任务的输入项与概念来源任务的 `form` 相似度 ≥ 阈值。
   - `cut_deps`：拷贝条目**此刻实际在用的版本**（被钉住的快照），之后与原料无关。
   - `keep_deps`：概念是原料的别名，组合时展开成原料，缓存条目直接依赖原料的版本，原料一变就随之过期、交给裁判。
   - 晋升可以叠加：用“读数字”概念学会的 parity 再晋升，就是第 2 层概念。
4. 每个候选都要“对得上宽度”（`_fits`）：被复用单元收到的输入宽度必须与它建立时一样，最后输出必须等于任务的类别数。

**对照臂**：`vcm_freeze_promo_comp0` 把晋升门槛设为 0（学完立即晋升），用来区分“整条组合可以被当作一个单元来寻址”
与“频繁 + 稳定才晋升”这两件事。`experiments/compose_readers.py` 绕开学习器的选择，强制指定读图器
（整条概念 / 逐层的 `in+hidden` / 只有第一层 / 微调 / 从零），单独回答“概念作为积木本身值多少”。

### 2.7 候选选择（v0.3–v0.5，`VCMConfig.selection`）

学一个新任务时有若干候选组合（从零 / 逐层复用 / 概念），要选一个继续训练。四种方式：

| `selection` | 做法 | 候选训练步数之和（5 个候选、预算 T = 500） |
|---|---|---|
| `probe`（默认，v0.1–v0.2） | 每个候选训练 `probe_steps` 步，在选择集（验证集前 `probe_val` 个样本）上比准确率；被选中的换一个新的 Adam 接着训到 T | 5k + (T − k)；k = 100 时 900 |
| `halving` | 逐步淘汰：每个候选先训 `probe_steps` 步，留下前 1/η，预算乘 η，再比……直到只剩一个，它接着训到 T；每个候选一直用自己的 Adam | η = 2、从 50 步起：5·50 + 3·50 + 2·100 + 300 = 900 |
| `finalists`（v0.5） | 每个候选先训 `probe_steps` 步，前 `finalists` 名接着训到 T 再比；每个候选一直用自己的 Adam | 5k + m(T − k)；k = 25、m = 2 时 1075 |
| `full` | 每个候选都训满 T 步再比（选择质量的上限参照，代价是 n 倍） | 2500 |

各方式最后都用同一条简约规则：准确率在最好者 `parsimony` 以内的候选里，取新参数最少的。
`probe` 的代码路径与 v0.2 完全一样（v0.1 的基准在相同命令下仍逐位一致）。

**诊断模式**（`curve_every`）：`full` 加上 `curve_every = 25` 时，每 25 步记录每个候选在选择集和另一份不相交的留出集
（验证集的下一批 `probe_val` 个样本）上的准确率，留出集只用来事后打分，不参与任何决定。
`experiments/selection_curves.py` 在这些曲线上重放各种选择规则（探测 k 步、曲线外推、逐步淘汰、全部训满、按留出集挑的天花板），
各规则只能看到自己付过费的那些步。〔实现选择〕曲线外推用 $a - b\,t^{-c}$（$c$ 取网格）做最小二乘，只接受上升的曲线。

**结果要点**（`results/selection/`）：逐步淘汰在同样计算下少漏选概念（250 个样本时 4 个两图任务里选中 3.4 个 vs 2.2 个），
但准确率不变——漏选的代价本来只有 0.3–0.7 个百分点，且与 1000 个样本选择集的噪声同级；全部训满只在 4000 个样本时有用（+1.1），
救回的是容量更大、起步更慢的“只复用第一层”方案。默认保持 `probe`。

〔实现选择〕`probe` 在选定后用一个新的 Adam 接着训练，`halving` / `full` 一直沿用每个候选自己的 Adam。
前者在 100–250 个样本时多约 0.4 个百分点（`--selection halving --halving-eta 10` 即“探测 100 步、不换优化器”的对照）；
给逐步淘汰的幸存者也换一次优化器，可能把两者的好处合起来，尚未在验证集上检验。

**Split CIFAR 上的选择（v0.5，`results/selection_cifar/`）**：CIFAR 每个任务的验证集只有 1000 / 500 张，切不出不相交的留出集，
所以曲线诊断改用 `--val-fraction 0.2`（留出训练池的 20%）和 `--probe-val`（CIFAR-100 取 500），让选择集保持学习器实际用的大小，
其余做留出打分集；代价是诊断运行的训练集少 11%（每任务预算 315 / 160 步，正式运行是 355 / 180 步）。
`experiments/selection_cifar.py` 在这些曲线上重放 16 条规则（含按留出集挑的天花板），然后读测试集上的学习器运行。

要点：CIFAR 上探测失败的方式很固定——冻结前 3 个卷积块的 bottom3 起步最快、终点最低，第 25 步时几乎总在前两名里（104 个决策中 103 个），简约规则又偏向它。
与探测同价的逐步淘汰在第 50 步就决出前两名，太早，只补回训满收益的 34% / 16%（CIFAR-10 / 100，验证集）。
`finalists`（探测 25 步、前 2 名训满）补回 78% / 73%，计算是探测的 1.37 / 1.10 倍（训满是 3.06 / 2.22 倍）；
测试集（3 个种子）上 +0.55 / +0.71 个百分点（训满 +1.28 / +0.50），总计算约为训满的一半。
它的上限在决赛名单：第 25 步的前两名几乎总是 bottom3 + bottom2，起步慢的 bottom1 进不去。
对 update 模式几乎没有影响，因为原地微调的复用层没有冻结带来的低天花板。默认保持 `probe`。

## 3. 已知局限（诚实清单）

- `form` 相似度只用输入像素的均值/标准差相关系数，对自然图像过于粗糙：Split CIFAR-10 中“飞机/汽车”与“鹿/狗”的 `form` 为 0，
  但低层卷积特征其实可以通用。更合理的做法是在单元自己的响应统计上比较（未实现）。
- 计算量按乘加次数估计，冻结层的反向传播也按完整网络计费（对 VCM 偏保守）。
- 任务路由用最近质心，在 Permuted MNIST 上近乎完美，但在类增量场景（任务身份是语义的）会失效；目前 CIFAR 只做任务增量。
- GRACE 本为模型编辑设计，用在分类持续学习上并不是它的主场；结果只说明“码本式补丁在此设定下的表现”。
  码本规则按官方实现（github.com/Thartvigsen/GRACE，`eps_expand="coverage"`）。
- 裁判只看 200 个反馈样本，统计误差约 ±2–3 个百分点，与 `tolerance = 0.02` 同一量级；判决本身带噪声。
- 晋升在神经层上的触发与被选用都依赖探测阶段的短训练，结果对随机流敏感（见 README 的讨论）。
- 组合式 MNIST（v0.2）：晋升出的概念输出的是来源任务的 logits（未归一化）。它作为读图器起步比 256 维特征慢，
  短探测（50–100 步）会漏选它；探测越长越能选中，但计算越多。概念冻结后会成为上限（数据多时不如微调）。
- 两图任务必须给任务编号（同一对图问的是不同的问题），目前没有“从问题推断任务”的机制。
- 候选选择用固定的 1000 个验证样本，即使任务只有 100 个训练样本；这比真实的少样本场景宽裕。选择的噪声（约 ±1.4 个百分点）
  与候选之间的差距同级，这是 v0.3 中各种选择方式差别不大的主要原因。
- `finalists` 只在 Split CIFAR 上验证过；在组合式 MNIST 上，概念读图器起步慢，第 25 步时可能进不了前两名（未测）。决赛名额固定为 2，按差距自适应的名额（`race`）在验证集重放里不如固定名额。
- v0.6 证伪实验的阈值网格来自预跑（永远接受、只在验证集上评估）。两个偏差让 CIFAR-100 上的网格放偏：预跑在验证集上评估时裁判改用训练样本，函数空间的降幅偏大；预跑永远接受，权重变化是增量的，而留下旧版本后是累积的。以后定网格应在与正式运行相同的反馈来源和决策方式下预跑。
- 模板只在 MLP 上实现：读图部分的层必须只作用在最后一维（`Linear`、`ReLU`）；CNN 要支持多图输入还需要把项目轴并进批维。
