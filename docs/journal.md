# 研究日志（白话版）

给不看代码的人读：每一步做了什么、为什么、结果怎样、下一步怎么定的。技术细节在 README、`docs/design.md` 和 `results/`。

## 这个项目在做什么

神经网络学新东西时会忘掉旧的（“灾难性遗忘”）。VCM 的想法是把网络拆成可以复用的“积木”（网络的层），学新任务时从旧积木里挑一套组合，
不够再造新积木。积木被改动时记一个版本号；旧任务下次被用到时，才检查它还能不能接受新版本，不能就退回旧版本（这叫“惰性”检查）。
常被一起使用、又一直没出过问题的组合，可以“晋升”成一块新的大积木。

## 做过的事

**v0.1：把系统搭起来，在标准基准上跑。** 基准是 Permuted MNIST（打乱像素的手写数字）、Split CIFAR-10/100（把图片分类拆成几个小任务）。
结果：VCM 几乎不遗忘，在 CIFAR-100 上比“每个任务训一个新网络”高约 4 个百分点；但计算量是它的 2 倍多。

**v0.2：专门测“晋升”有没有用。** 造了一个组合式任务序列：先学认数字，再学“两个数字之和”“是否相等”等。
结果：每个任务只有 100–250 个样本时，晋升出的“认数字”积木让准确率高 1–3 个百分点；样本一多，好处就没了。

**v0.3：挑积木组合的方式。** 原来每个候选组合只试训 100 步就比较，可能漏掉起步慢的好组合。试了几种更细的挑法。
结果：漏选确实存在，但损失很小（0.3–0.7 个百分点），不是瓶颈。

**v0.4：查相关工作，复现最接近的方法 MNTDP。** 结果：VCM 在 MNTDP 做不到的事上赢（例如按语义复用上层），
在两者做同一件事时 MNTDP 持平或更好；它多出来的准确率全部来自“每个候选都训满再挑”，代价是 2–3 倍计算。

**v0.5：能不能少花计算拿到“训满再挑”的好处（Split CIFAR）。**
结果：与原做法同价的“逐步淘汰”没用；“先试训 25 步，再把前两名训满”在验证集上拿回七成多好处，计算约为训满的一半。
测试集只有 3 个种子，方向对但统计上不显著（p = 0.084）。这是一项旁支的工程改进，不是论文的主线。

## 2026-10-28：查新，主线主张被收窄

为了判断项目有没有发论文的价值，读了三篇最可能撞车的论文原文：

- **DEN**（ICLR 2018）：新任务时继续训练共享的神经元；训完检查每个神经元的权重变了多少，变太多就复制一份，旧任务用旧的那份。
  这和 VCM“积木原地更新、旧任务不行就退回旧版本”是同一个思路，早了 7 年。
- **APD**（ICLR 2020）：共享参数随新任务更新，同时回头调整每个旧任务的私有参数，让旧任务的权重尽量不变。
- **Mendez & Eaton**（ICLR 2021）：先学怎么组合积木，再原地更新积木（用微调 / EWC / 回放），没有版本与回退。

所以“版本号 + 退回旧版本”本身不新。VCM 剩下的区别只有：
1. 用**旧任务的准确率**判断要不要退回（DEN、APD 看的是权重变了多少）；
2. 等旧任务**被查询时才检查**（DEN、APD 是训练时就处理所有旧任务）；
3. 以整层为单位，并且要为每个旧任务存 200 个样本用来检查（DEN、APD 不存数据）。

这些区别值不值得一篇论文，取决于一个还没做的实验。

## 下一步：先做最便宜、能直接证伪的实验

在 VCM 内部只换“判断要不要退回”的规则，其他一概不动：
- (a) 现在的做法：看旧任务在留出样本上掉了多少准确率；
- (b) DEN 式做法：看共享层的权重变了多少，不用任何数据；
- 再加“从不退回”和“总是退回（等于冻结）”两个端点。

每种规则扫几个阈值，画“遗忘 vs 多存的旧版本（内存）”曲线。
如果 (a) 的曲线不明显优于 (b)，“函数空间 + 惰性检查”这条主线就不成立，项目要换主张，或者老实写成技术报告。
这个实验在 CPU 上就能跑（几个小时），值得在租 GPU 做大规模实验之前先做。

“前 2 名训满”的补种子实验，另一个会话正在分支 `claude/compassionate-hopper-gmspkb` 上做，已事先登记了计划；这边不重复。
